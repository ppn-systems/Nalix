# Nalix.Environment

## Role

Bootstrap infrastructure layer. Provides system environment discovery, secure filesystem preparation, configuration loading, low-level I/O primitives, memory management (DataReader/DataWriter/BufferLease), and time/hashing utilities.

**Dependencies:** `Nalix.Abstractions`

## Directory Structure

```
Nalix.Environment/
├── Configuration/       # ConfigurationManager, Binding/ (INI config loader + AOT-safe binding)
├── Extensions/          # Extension methods for environment utilities
├── Fragments/           # FragmentAssembler, FragmentHeader, FragmentStreamId (large packet reassembly)
├── Hashing/             # XxHash32 (non-crypto hash for checksums)
├── IO/                  # Directories (cross-platform path helpers, Unix permission management)
├── Internal/            # Internal helpers
├── Memory/              # BufferLease, DataReader, DataWriter (core I/O primitives)
├── Options/             # Configuration option POCOs
├── Random/              # CSPRNG helpers
├── Sequencing/          # SequenceCounter (anti-replay sequence tracking)
├── Time/                # Clock (Unix timestamps), TimingScope (perf measurement)
├── DiagnosticsEvents.cs # EventSource-based diagnostics
```

## Key Components

### Memory Primitives (Hot Path)

| Type | Purpose |
| :--- | :--- |
| `BufferLease` | Pooled byte buffer with ref-counted lifecycle. Implements `IBufferLease`. |
| `DataReader` | Zero-copy binary reader operating on `ReadOnlySpan<byte>`. |
| `DataWriter` | Binary writer with auto-growing buffer, backed by pooled memory. |

These are the backbone of all serialization and networking I/O. They MUST remain zero-allocation on the hot path.

### Configuration System

- `ConfigurationManager` — INI file parser and POCO binding engine.
- Source generator (`ConfigurationGenerator` in AutoGenerated) creates AOT-safe binders.
- Config option classes are decorated with `[ConfiguredIgnore]` / `[IniComment]` attributes from Abstractions.

### Fragment Assembler

Reassembles large packets split across multiple frames:
- `FragmentHeader` — 12-byte header with stream ID, index, total count.
- `FragmentAssembler` — Stateful assembler tracking in-flight fragment streams.

## Performance Rules

- `DataReader` and `DataWriter` are `ref struct`-like usage patterns — work with spans.
- `BufferLease` uses reference counting — always dispose properly.
- `XxHash32` is for checksums only, NOT for cryptographic use.
- Directory operations use `stackalloc` where possible for path construction.

## Anti-Patterns

- Do NOT use `DataReader`/`DataWriter` for non-binary formats.
- Do NOT bypass `BufferLease` pooling with direct `new byte[]` allocations on hot paths.
- Do NOT use `XxHash32` for security-sensitive hashing.
